# Technical Architecture Template

Write `doc/technical-architecture.md` with this structure:

## 1. 架构总览

- 系统由哪些主要层或子系统组成
- 入口在哪里，执行主链路如何启动

## 2. 关键组件与职责

- 列出核心模块、服务、包或进程
- 说明它们之间的关系和职责边界

## 3. 数据与状态流

- 请求、任务、事件或命令如何流动
- 状态存储在哪里
- 是否存在缓存、队列、数据库或本地文件依赖

## 4. 外部依赖与集成

- 第三方服务、SDK、数据库、中间件、平台能力
- 对应配置入口和适配层路径

## 5. 构建、运行与部署

- 本地开发方式
- 构建产物
- 部署/发布线索

## 6. 架构特点与风险

- 明确已观察到的优点、限制、耦合点、单点风险
- 避免泛泛而谈

## Writing guidance

- 优先描述真实结构，不要先贴“分层架构”“微服务”“插件化”标签再找理由。
- 如果仓库规模较小，可以按模块而不是按分层来组织说明。
