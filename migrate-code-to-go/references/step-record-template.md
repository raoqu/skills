# Step Record Template

当某一轮迁移明确完成了计划中的一个节点或子节点时读取本文件，并在目标仓库的 `go_migration/steps/` 下生成对应记录。

## 文件名规则

使用可排序、带时间的文件名，推荐：`YYYYMMDD-HHMMSS-<node-id>.md`。

示例：`20260411-153045-P2.1.md`

## 模板

```md
# Migration Step Record

- 记录时间：2026-04-11 15:30:45 +08:00
- 节点编号：P2.1
- 节点标题：示例标题
- 本轮目标：

## 计划对应关系

- 对应 `go_migration/plan.md` 的部分：
- 前置节点：
- 本轮完成定义：

- 为什么先迁这个节点：

- 做了哪些关键判断：

## 变更范围

- 行为差异：

```

## 使用规则

- 一次完成一个节点或子节点时，优先写一份独立记录；只有在多个子节点在同一轮紧密耦合且同时完成时，才合并记录。
- 记录要聚焦“本轮完成的迁移事实”，不要把未来猜测写成已完成事项。
- “关键差异”必须写相对原项目差异性较大的变更，不要只重复实现细节。
- “遗留问题”和“风险评估”必须明确写出当前仍未解决的点；如果确实没有，也要显式写“无”。
