# Dependency Migration Log Template

当迁移涉及第三方依赖、运行时框架、数据库驱动、HTTP client/server、任务队列、ORM、校验库、序列化库时读取本文件。

为每个关键依赖记录一条独立条目，方便后续多轮迁移复用。

- 原用途：
- 原项目使用位置：
- Go 落地位置：`go_migration/...`
- Go 候选方案：
- 最终选择：
- 决策类型：成熟三方库 / 自实现 / 维持外部服务 / 暂缓迁移
- 选择原因：
- 复杂度判断：简单功能 / 复杂模块 / 基础设施能力
- 不兼容点：
- 兼容策略：
- 需要封装适配层吗：是 / 否
- 示例落地位置：
- 已验证内容：
- 待验证内容：
- 风险备注：

## 记录规则

- 如果同一依赖在多个节点复用，统一引用同一个依赖编号。
- 若决策发生变化，保留旧结论并补充“变更原因”，不要静默覆盖。
- 如果 Go 侧不存在成熟替代品，明确记录“自实现”或“维持外部服务”。
- 对复杂模块优先评估成熟 Go 库；若选择自实现，必须说明为什么第三方库不合适。
- 对简单功能若决定不引入依赖，明确记录“避免额外依赖”的理由。
- 对许可证、性能、并发安全、协议兼容性问题单独标注。
