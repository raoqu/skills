# Module Analysis Template

当某个原项目模块复杂、会跨多轮反复阅读，或依赖替换决策需要长期复用时读取本文件，并在目标仓库的 `go_migration/docs/analysis/` 下创建分析文档。

## 适用场景

- 模块行为复杂，单轮内无法完整迁移。
- 同一模块预计会被多个计划节点引用。
- 需要记录协议、状态机、隐式副作用、框架魔法、边界条件或依赖选择理由。
- 当前已有分析文档不够覆盖新问题，需要补充一份主题化分析。

## 文件名建议

- `<module>.md`
- `<node-id>-<module>.md`
- `<module>-edge-cases.md`
- `<module>-dependency-decision.md`

保持文件名稳定、可搜索；新增补充文档时不要覆盖不相关分析。

## 使用规则

- 把复杂分析放在这里，不要让 `plan.md` 或 `progress.md` 承载大段模块解读。
- 若某份分析文档只覆盖部分问题，在文件顶部说明范围，缺失部分可追加新的补充文档。
- 在 `plan.md`、`progress.md`、`steps/` 记录中引用相关分析文档路径，避免重复分析原代码。
