# Execution Loop

当需要继续上一次迁移、决定本轮做什么、或控制上下文读取范围时读取本文件。

## 单轮循环

1. 查看 `go_migration/progress.md`，确认上轮停在哪个节点。
2. 查看 `go_migration/plan.md`，把当前节点标记为 `in-progress`。
3. 如果节点依赖第三方库决策，查看 `go_migration/dependency-mapping.md` 对应条目。
4. 只读取当前节点需要的源码、测试、配置、接口定义，以及 `go_migration/` 下对应的已有 Go 代码。
5. 明确本轮迁移目标对应的原始目录；忽略仓库中与当前节点无关的其他源码或文件目录。
6. 在 `go_migration/` 下实现最小可验证增量。
7. 运行当前节点规定的验证。
8. 更新 `go_migration/progress.md`：
   - 本轮完成内容
   - 验证结果
   - 剩余问题
   - 下轮节点
9. 若决策变化，回写 `go_migration/plan.md` 或 `go_migration/dependency-mapping.md`。

## `go_migration/progress.md` 建议结构

- 当前阶段：
- 当前节点：
- 已完成节点：
- 本轮改动摘要：
- 本轮验证：
- 当前阻塞：
- 下一节点：

## 上下文控制规则

- 不重新加载整个代码库，只读取当前节点相邻上下文。
- 如果一个文件超过当前节点所需范围，只读相关片段。
- 如果仓库存在多个源码根目录，只读取当前计划节点明确涉及的目录。
- 如果发现新的架构事实会影响多个后续节点，先回写计划文档，再继续代码实现。
- 如果当前节点超出单轮能力，优先拆分计划，而不是硬做到底。
