# Validation Checklist

当需要为迁移节点设计或补充验证时读取本文件。

## 通用检查

- `react_migration/` 是否保持为独立、可理解的 React/Vite 项目结构
- 目标 `package.json` 是否仍符合 `pnpm 10.20 + TypeScript + Vite 6.3.5 + React 19.1.0`
- 是否已经删除或隔离 Vue、Angular、Svelte、webpack、CRA、Yarn、npm lock 等旧栈残留
- 关键入口是否可运行
- 路由、导航、布局和页面分组是否仍能追溯回原项目的信息架构
- 配置加载、环境变量命名和 API 地址注入是否与原实现兼容
- 错误态、空态、加载态和权限分支是否兼容
- 时间、时区、精度、空值语义和格式化行为是否一致

## 工具链与依赖策略

- `packageManager` 是否明确为 pnpm 10.20 系列
- 是否不存在 `package-lock.json`、`yarn.lock`、`.yarn/`、旧 CLI 配置等目标项目不再需要的产物
- `tsconfig`、`vite.config.ts`、`index.html`、入口文件是否彼此一致
- 复杂模块若引入第三方 React 库，是否验证了行为契约、维护度、许可证、打包体积和关键边界
- 简单功能是否避免了不必要的新依赖
- 如果目录结构有意偏离原项目，是否在计划或步骤记录中说明原因

## 路由与页面

- 路由路径、动态参数、重定向、守卫和默认落点一致
- 页面级懒加载、布局嵌套和导航高亮一致
- 页面标题、面包屑、权限控制和空白态一致
- 滚动恢复、锚点跳转和返回行为一致

## 数据与交互

- API 请求参数、默认值、错误处理、重试和取消行为一致
- 状态管理更新顺序和副作用触发时机一致
- 表单校验、默认值、脏值检测和提交流程一致
- 上传、下载、轮询、WebSocket 或长连接行为一致

## 样式与渲染

- 关键布局、断点、自适应行为和滚动容器一致
- 主题变量、样式隔离、类名策略和全局样式顺序一致
- 图表、表格、虚拟列表和 Portal 类组件在 React 中表现正常
- SSR/SEO 若原项目依赖此能力，是否已明确记录“保留 / 放弃 / 改造”的决策

## 最低验证策略

若原项目测试薄弱，至少补下面之一：

- 1 次 `pnpm build`
- 1 次 TypeScript 类型检查
- 1 条关键路由冒烟路径
- 1 个关键 API 流程对比
- 1 组核心交互或表单的人工验收步骤
